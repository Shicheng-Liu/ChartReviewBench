How ChartSandbox Works

ChartSandbox turns LLM-generated chart code into an executable, observable, and reproducible agent task—not just a text answer.

1. Task package

task.yaml defines the instruction, subgoals, verifiers, and budgets. workspace/ contains the input files.

→
2. Fresh run workspace

The inputs are copied into an isolated writable directory. The original task remains unchanged.

→
3. Agent starts

The LLM receives the task, visible files, available tools, and remaining step budget.

↓
4. Agent uses tools

read, write, list, execute_python, view_image, and finish.

⇄ code →
← feedback
5. Persistent Python worker

Runs code with state across steps and returns output, tracebacks, timeouts, changed files, and image artifacts.

The agent uses each observation to revise its code and repeat the loop.

↓
6. Finish or budget limit

The loop ends when the agent calls finish, reaches the step limit, or exceeds the wall-time budget.

→
7. Verify and score

Execution, data, and visual verifiers evaluate each weighted subgoal.

Hidden oracle → verifiers only
→
8. Save the run

result.json stores scores and metrics; trajectory.jsonl stores every tool call and observation.

Runtime feedback to the agent

  • Python stdout, stderr, tracebacks, and timeouts
  • Files changed and images created
  • Workspace file contents and metadata
  • Image artifact type and dimensions
  • Tool, path, timeout, and kernel-state errors

What the benchmark records

  • Complete tool-call trajectory
  • Per-subgoal pass/fail status and score
  • Weighted final score and progress curve
  • Steps, wall time, and tool usage
  • Final code, data files, and chart artifacts
Current scope: the MVP uses a persistent local Python subprocess, path-checked file tools, execution timeouts, and best-effort network blocking. The real LLM agent and visual judge are still integration points. The runtime is not yet a hard security boundary; untrusted code should eventually run inside Docker, gVisor, or another system-level sandbox.

In short: controlled execution + iterative feedback + reproducible verification.
